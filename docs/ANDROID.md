# Android tablet edition

AniVerse Android 0.4.6 uses a Kotlin host and the shared React UI. It is a browser with anime metadata and app-private offline playback, not a content provider. The Windows release remains independently versioned (2.2.1).

## Devices and support

Android 15/API35 or newer, with an up-to-date WebView supporting origin-restricted messages and isolated profiles. Primary tablet target: **Galaxy Tab S10+**. Samsung DeX and BlueStacks/freeform Android windows are allowed regardless of reported device smallest width. The actual current window controls the layout; a compact window uses bottom navigation and preserves the user's wider-window preference. Touchscreen hardware is optional; mouse and keyboard remain usable. Resize, rotation and display changes preserve the main WebView and inline source session. OS/window-system or physical-device compatibility still needs device-specific verification; emulator screen tests do not certify Samsung hardware or an alpha BlueStacks engine.

## Using the tablet app

- **Settings → Appearance:** choose floating bottom tabs or a vertical navigation capsule, Light glass or Dark glass, Android wallpaper accent or a custom colour, and reduced motion. The logo and profile float in opposite top corners. Smaller search/navigation capsules overlay a full-width canvas without a broad footer plate; search sits above bottom navigation when selected. The vertical rail has a persistent show/hide control. Both navigation layouts retain every destination. Android appearance preferences stay separate from the Windows backup format.

- **Sources → Add source:** paste a public HTTPS website URL, optionally name it, then save. Each card has Enable, Open, Edit, Clear data and Remove. **Refresh sources** reloads saved entries, and the bottom search dock **Refresh** retries current data/metadata. Pull down from the top of the content to refresh; player and carousel gestures remain separate. There is no TXT import or small fixed source-count cap. Authentication stays inside the selected source's browser profile. Original website players and audio/server controls remain in use.
- **Watch episodes** opens the original player inside the AniVerse watch screen, beside the episode list. Use the player's controls for playback, captions and quality. The app audio controls read available SUB/DUB options from the source and confirm its selected control; they do not invent availability. **Show website** reveals the source inside the same pane for sign-in, manual navigation and source controls. **Player only** restores the focused view. The browser opened from the Sources table is for full-site browsing.
- **Local watch → Import video:** use Android's file picker. AniVerse copies and validates the file in app-private storage. Add UTF-8 SRT/WebVTT from the card; SRT is normalized to WebVTT for reliable seek/resume. Play in airplane mode, resume, then Remove saved copy. Originals remain untouched. Embedded captions depend on Media3/device support. Attaching a replacement subtitle keeps the previous one if validation or import fails.
- **Player:** double-tap left/right to seek ten seconds; swipe vertically left for brightness or right for media volume. Lock touches for travel; use Unlock touches to restore controls. Mini player uses Android picture in picture where supported. Android has no desktop 4K enhancement control/pipeline.
- **Downloads:** tap **Download** below the currently playing episode. AniVerse resolves the active source media without asking for a URL, and keeps the source session context native-only. Direct video files and supported non-DRM HLS video-on-demand can be saved. Completed downloads appear in Local watch. Confirmed SUB/DUB selection is retained in queued/saved metadata and Downloads audio filters; older records, imported files and unconfirmed audio remain unknown. Queue, progress, pause/resume, retry/restart and cancel are native. A direct-file resume needs valid byte ranges and a validator; otherwise the file restarts safely. A manual file-link form remains an optional fallback. Expired source links must be reopened in the player. DRM, live streams and access-control bypass are unsupported. Saved copies remain after leaving incognito until explicitly removed.
- **Settings → Security & privacy → Block source ads:** enabled by default for existing and new sources. A packaged AdGuard DNS-domain snapshot plus AniVerse's existing cosmetic rules filters source requests, frames and service-worker requests; pop-up windows stay blocked. Turning ad filtering off never disables the mandatory network/TLS guard. Domain filtering cannot remove every same-origin media ad. Rules update with the app; source pages cannot install filters. Attribution and supported filter syntax ship in APK assets.
- **Settings → AniList & MyAnimeList:** paste a valid OAuth access token into the native dialog, verify the actual account, then sync manually. A client/app ID or client secret is not an access token. The token stays outside JavaScript and source profiles, encrypted with Android Keystore. Expired tokens require reconnecting; automatic refresh/login acquisition is not included in this edition. Sync was validated with controlled fixtures, not a real user account.

## Android release updates

Open **Settings → Android updates**, choose **Check for updates**, then **Install** when a newer stable Android release is available. Updates use this project's public GitHub Android releases; Windows' latest release is ignored. Debug and fixture builds do not offer production updates.

If 0.4.5 refuses to launch on BlueStacks/DeX because of its old tablet-size notice, install 0.4.6 manually over the existing app. The blocked screen cannot open the in-app updater. Keep the app installed so Android can retain its data; working tablets can use Settings updates normally.

The app downloads only after your action, verifies the APK against the release checksum and the installed app's signing identity, rejects another package or a non-increasing version code, then opens Android's installer. Android may first ask you to allow installation from AniVerse: grant that permission in the system settings, return, and choose Install again. You confirm installation in Android; the app never installs silently. App-private APK storage is exposed only through a nonexported, temporary read-grant provider scoped to the update cache.

## Security and privacy

Android application UID storage and the platform WebView renderer sandbox form the OS boundary. Sources get separate native browser profiles and **no native message bridge**, file grants or camera/microphone/location permissions. The packaged app main frame alone has an origin-restricted message channel with input/concurrency limits. Certificate errors are rejected; cleartext is disabled in release. File IDs/paths are native, canonical and private; Android backup/device transfer is disabled. Token verification uses official provider endpoints in release and Keystore-encrypted storage.

Provider imports use process-wide bounded workers, native inactivity/absolute deadlines, cancellation-aware query/open and nonblocking polled reads. Terminal replies release admission once. Late results cannot publish media or replace a prior subtitle. A provider that ignores cancellation can retain only the bounded provider workers; ordinary native controls remain independent.

Private website sessions use disposable **named WebView profiles**, deleted on close or next startup after interruption. They are not guaranteed memory-only; no anonymity is promised. Incognito/private-title rules suppress new library/history/progress/learned methods and sync while active. Already saved user-requested downloads/imports remain until removed. Pending edits are skipped while their title is private; existing external records are not erased.

Public-address checks run before native requests and source callbacks; TLS checks remain active. DNS resolution races, every WebView request/redirect/WebSocket class, OS/firmware/codec bugs and browser vulnerabilities are not ruled out. Treat these checks as app safeguards, not a VPN/firewall or a guarantee that arbitrary sources are safe. See [Privacy](../PRIVACY.md), [Security policy](../SECURITY.md) and [security architecture](SECURITY-ARCHITECTURE.md).

## Build and signing

Install Node 22+, Android Studio, Java 17+ compatible with Gradle 9.6, Android SDK platform 37 and build tools. The wrapper pins Gradle 9.6.0 SHA-256; AGP is 9.5.0. This checkout uses Android Studio's JBR. Set JAVA_HOME and ANDROID_HOME if installed elsewhere.

Run `npm ci`, then `npm run android:debug` or `npm run android:release` from the repository root. Both rebuild `dist/android` before packaging. Gradle build/user/project caches, Android user configuration and temp output are contained under `test/cache/android-0.1.0`. The release task also runs Android lint. Opening the Gradle project alone does not rebuild web assets; run `npm run android:ui` after UI changes.

Release signing uses `ANIVERSE_ANDROID_KEYSTORE`, `ANIVERSE_ANDROID_STORE_PASSWORD` and `ANIVERSE_ANDROID_KEY_PASSWORD`, alias `aniverse-tablet`. The build script can instead read ignored `config/android-signing.json` with keystore/storePassword/keyPassword fields. Never commit the key/passwords. Securely back up the existing Android signing key: later APK updates need that identity. The APK is copied to `release/android-0.4.6/AniVerse-Android-0.4.6.apk`; the build derives the output version from `android/app/build.gradle.kts`. The shared `test/cache/android-0.1.0` cache path remains stable across releases.

Normal `android:debug` uses official metadata networking and package `app.aniverse.tablet.debug`. It contains no fixture provider or local API redirection. The explicit `npm run android:fixture` / Gradle `-PaniverseFixture=true` test build instead uses package `app.aniverse.tablet.fixture`, local fixture networking and a nonexported test provider; its account-entry UI is disabled and its header identifies it. Test instrumented source sets are enabled only by that explicit flag. Release remains `app.aniverse.tablet`, signed, with app debugging disabled and no fixture endpoint/provider. Publish the release APK, and keep functional testing on official metadata and the actual privately configured Windows sources.

## Validation scope

Use owned Android Studio emulators only; a physical tablet connection is unnecessary. The user-facing emulator is emulator-5580; isolated validation now uses emulator-5584 so tests cannot overwrite an actively used profile. Every ADB command must name the owned emulator serial. Maintained harnesses are under `test/e2e/android-live.mjs`, `test/e2e/android-layouts-live.mjs`, `test/e2e/android-downloads.mjs`, and `test/android/`; reports live under `test/artifacts`. Emulator screen profiles approximate tablet layouts and do not certify Samsung One UI, device codecs, DRM or physical hardware. The initial API35 system image has an old patch/WebView and triggers the app's warning. Initial software-rendered host emulator runs crashed in qemu (0xc0000005), including with HardwareDecoder disabled. Switching to the actual host NVIDIA OpenGL renderer, with emulator Vulkan/HardwareDecoder disabled, completed native video and source playback checks. This changes only emulator configuration, not product security or the tablet decoder.

## Android 0.4.6 changes

The tablet shell follows the user's floating block layout. Search is at the bottom in both modes, stacked above horizontal navigation, with separate top logo/profile capsules. Chrome uses translucent surfaces, localized24px blur and Android system accent colours; custom accents and reduced motion remain available. Pull-to-refresh shares the existing Refresh action. Android hover previews are removed so a long-press context menu cannot collide with a second preview; the touch menu scrolls inside the content's safe area. The hero uses a smooth poster-card strip. Navigation/search capsules are smaller and overlay a full-width canvas without a broad footer/background plate; the vertical rail has a persisted show/hide button. The native player stays clipped away from app controls.

The player Download action uses its owned playback session, with native-only media context and stale-navigation checks. Direct transfers retain range validation. HLS VOD downloads use a private per-item Media3 cache and offline playback has no network fallback. Native source credentials are never returned to the UI. Downloads retain bounded observed Accept, Accept-Language, Authorization and allowed X-* headers. A verified HLS graph can retain separately observed CDN contexts; each destination receives only its own captured credentials, with conflicts rejected and no inheritance to unobserved origins. Database schema 3 adds nullable audio metadata while retaining existing files, transfers and profiles; old audio is unknown. Source-confirmed audio selection is carried into new queued/saved items and Downloads filters.

The old600dp device rejection was removed after a user reported BlueStacks/DeX startup failure. The manifest permits normal/compact screens, full-user orientation, resizing and non-touch input. Native `WindowMetrics` reports actual usable window dimensions/size classes; `smallestScreenWidthDp` is informational. A trusted resize event updates cached window metadata. Source/application native isolation and WebView feature requirements remain mandatory.
