# AniVerse 2.0.1

Embedded Rust protection and temporary Diwali × Halloween branding.

- 🛡️ An embedded Rust/WebAssembly policy validates source URLs, canonical IP representations, source navigation and app assets. It has no imported host APIs, bounded input and bounded memory.
- 🔒 Source protection stays active when ad blocking is off. Unsafe local-network destinations, privileged schemes and credential-bearing URLs are rejected; explicit local source origins and ordinary public CDNs remain supported.
- 🧩 Stronger software controls: exact app-origin trust, own-property RPC methods, input/call budgets, an app content policy, read-only media grants and explicit worker/subframe Node restrictions.
- 📦 Production binaries disable Node environment, RunAsNode and main-inspector entry points and validate ASAR integrity. No Rust runtime or system service needs to be installed by users.
- 🪔 Temporary vector logo, running-window icon and lamp/pumpkin buffering animation use the festive palette. Reduced motion is respected. All seasonal branding and buffering revert on January 1, 2027; opting out of the palette restores them earlier. The original cat assets remain intact.
- 🎬 The source's original video, audio, controls, quality selection and navigation remain in use. A disposed-iframe race found during live testing is handled safely.
- 📖 Colour-coded in-app highlights describe the update.

These protections reduce identified risks; they do not make every website or dependency safe. DNS checking has latency and resolver/connection race limits. Physical TV output, physical audio quality and installer/update installation are separate from the software checks. See [security boundaries](../SECURITY-ARCHITECTURE.md).

Validation: typecheck, lint and 233 unit tests passed. The final signed 2.0.1 executable passed 11 production security, normal/4K playback, navigation and seasonal-restoration checks. Additional development regressions covered all six upscaling presets, timing fallback, source/privacy and Workspace functionality.

Live ordinary-title testing confirmed decoded playback on 7 of 14 configured website sources. The other seven were also unconfirmed on the previous 1.5.8 release, including the same two navigation timeouts. No new playback failure was observed in that comparison; this is not a claim that every source or episode plays. Tests used isolated, muted profiles and did not measure speaker or physical TV output.
