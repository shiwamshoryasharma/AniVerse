# AniVerse 1.5.3

## Changed

- **Three actual interface layouts:** Classic retains the original collapsible rail; Studio provides a permanent labelled workspace sidebar and dashboard navigation; Cinema uses horizontal navigation, a wide player and an episode shelf beneath playback. Accent and font remain separate preferences. Existing saved style IDs and imported presets stay compatible.
- A prominent **Cast to TV** button now appears above every loaded episode player. Native/local media opens the existing cast controls.
- Website episodes can **mirror the selected source view and its audio** to a Google Cast receiver. Standard output is 1080p H.264/AAC; optional Anime4K output is 3840 × 2160 HEVC/AAC. Filtering and encoding run on the casting device with embedded FFmpeg/FFprobe.
- **In-app changelogs** include coloured Added/Improved/Fixed cards, feature icons and links to the relevant app screens. New-version highlights appear automatically once acknowledged per profile. The header’s What’s new button and Settings → Changelog reopen the history.
- Profile/appearance and interface-layout settings retain distinct icons.

## Casting behavior

Only the selected, owned website view is captured, with optional audio from that view. Desktop windows, camera, microphone and unrelated application audio are excluded. Capture uses a single-use grant restricted to the app’s trusted top frame. Stop casting, source navigation, leaving the episode and app shutdown end capture and owned encoder work.

Website mirroring has a short live-stream delay. Keep the website player visible and use its controls to seek. Protected video may not permit capture. 4K needs a Vulkan-capable sender, adequate encoding/network capacity and a 4K HEVC-capable Google Cast receiver. The TV still decodes the video. No website media URLs are extracted, and no system FFmpeg installation is needed.

Google Drive remains app-data only, with the unchanged **AniVerse Sync/aniverse-backup.v1.json** protocol.

## Validation

Typecheck, lint, 161 unit tests, hidden Electron layout/changelog/native-and-website cast UI checks, Drive/Anime4K regression checks, real selected-webview audio/video capture, and real embedded 1080p H.264 / 4K HEVC/AAC encoding are covered. Capture tests use production IPC validation and a controlled receiver transport.

No physical TV, real Google account, live website compatibility certification, Windows install/uninstall/update-install or image-based model-quality check is claimed. Test artifacts are kept under test/artifacts/.
