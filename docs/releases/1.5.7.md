# AniVerse 1.5.7

Cast with Chrome and keep AniVerse sharp.

## Changes

- **Chrome-backed casting:** both episode and native-video menus offer **Find TVs with Chrome**. AniVerse launches installed Google Chrome in a dedicated app-owned profile, discovers receivers through Chrome’s Media Router and starts tab mirroring. It does not automate or copy the normal Chrome profile.
- **Selected player only:** website capture retains the owned-view, user-gesture and single-use grant boundary. The sender’s embedded encoder produces H.264 or optional Anime4K HEVC 4K; the Chrome companion receives this stream over loopback. Local videos use the existing token-protected media server. No source URL extraction, desktop capture or security bypass is added.
- **Sharp UI:** removed the cast-dialog backdrop blur. The native chooser stays within the video area and closes when another player menu opens. Opening either chooser does not set app zoom, DPI or Windows display mode.
- **Distinct protocols:** Windows wireless display is a separate optional Miracast section. Windows projection can change desktop resolution/scaling; Chrome tab casting does not use it.
- **Lifecycle:** cancellation prevents late native connections. Closing/navigating the companion or ending a route tears down owned Chrome/media resources. An unused discovery window closes after two minutes.
- **Duplicate names:** when Chrome reports several receivers with the same friendly name, AniVerse loads the selected player and asks the user to choose through Chrome’s native Cast menu. It does not silently pick the first matching name.

## Use

Choose **Cast to TV → Find TVs with Chrome → your TV**. Keep AniVerse open with the episode playing. If Chrome asks you to choose between identically named TVs, use **Chrome’s Cast menu → Sources → Cast tab** in the companion window.

Chrome must be installed. The companion contains only the selected player; keep private desktop content out of the optional Windows projection route.

4K processing stays on the sender. A 3840 × 2160 input is supported where Chrome can decode HEVC, but Chrome negotiates the TV’s actual output quality. This release does not guarantee 4K tab mirroring or protected-video capture.

## Validation

TypeScript, lint, 188 unit regressions, nine packaged Electron feature checks, ten packaged Workspace checks and installed Chrome playback checks cover this change. The Chrome runtime check decodes an opened MP4 and embedded 3840 × 2160 HEVC HLS, verifies advancing frames/media time and closes the isolated process. Receiver-route behavior is additionally covered with a controlled driver.

No TV announcements were visible on the test host; the user confirmed the TV was off/unavailable. Physical-TV connection, TV output resolution and TV lip sync remain unverified.
