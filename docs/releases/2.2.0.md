# AniVerse 2.2.0

Learn source navigation once, combine browse filters, and keep untrusted input bounded.

- **Reusable source methods.** AniVerse remembers successful search controls, result selectors and episode-list steps per source. New series reuse those methods, including after restart. Changed selectors/layouts fall back to ordinary discovery and can be learned again. Explicit recipes take precedence.
- **Checkbox filters.** Genres, Themes/Tags and Formats support multiple choices, search, selected counts and Clear all. Isekai and the available harem categories are searchable themes; Ecchi, Mecha and Sci-Fi remain genres. Filter state survives reload and Reset filters clears it.
- **Remove repeated work.** Navigation avoids fixed page padding, empty preference waits and autoplay delay when the player is already playing. DUB/SUB filter changes no longer request the unused ALL grid. Existing animations and player features remain.
- **Stronger security boundaries.** All successful provider callbacks must match their initiated transaction. Source text metadata is limited to 8 MiB, with streamed-byte checks and cancellation; video continues through its existing browser/player path. Direct Cast parsing rejects malformed fields, limits each frame to 1 MiB and closes incomplete frames after 10 seconds. These are application budgets.
- **Preserve privacy.** Learned methods contain bounded structural selectors and steps, expire after 30 days and stay bound to the configured source origin. Incognito, private titles and recipes with caching disabled do not read or persist normal learned methods. Existing sessions, original website players, source request protection and stable Drive backup format remain.

Local fixture measurements: different-series navigation improved from 25,001 ms to 3,172 ms; the next episode from 8,845 ms to 170 ms. Restart and changed-layout fallback were exercised. This is a controlled navigation/DOM measurement with a playing probe, not proof of a remote site's loading speed or decoded playback.

Security review used offline source inspection and local hostile-input fixtures. No attacks were sent to source websites. Release validation results are recorded separately under `test/artifacts/`.
